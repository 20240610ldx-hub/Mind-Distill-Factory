# Post-Review Tuning Guide · 实战测试后的调优指南

> **本指南的地位：** 管线的第 7 步——在 quality-reviewer 给出 PASS 裁决、Skill 安装后，
> 用户进行实战测试对话，发现实际输出与设计意图之间的偏差。
> 本指南规范化了"从测试对话中提取缺陷→定位 SKILL.md 中的薄弱条款→精确修补"的流程。
>
> **谁使用它：** 人类审阅测试记录后，指导 skill-assembler 执行修补；
> 或 quality-reviewer 在未来版本中增加"实战对话审查"维度时引用。

---

## 一、为什么需要这一步

quality-reviewer 的 7 维审查是**静态审查**——它检查 SKILL.md 的文本是否合规，
但无法预测**模型在运行时是否真正遵守了这些规则**。

实战测试揭示的是一种特殊的缺陷：**规则写了，但模型没执行**。
根本原因通常是：

| 缺陷类型 | 根因 | 修复策略 |
|----------|------|----------|
| 规则太抽象（"不要列举"） | 模型不知道用什么替代 | 补充**正面替代工具箱** |
| 规则没有量化（"不要重复"） | 模型不知道"多少次算重复" | 加入**具体数字上限** |
| 规则之间有冲突 | 遵守 A 就违反 B | 明确**优先级排序** |
| 规则只在一处提及 | 长文中注意力衰减 | **交叉引用**：在多个章节重复提醒 |
| 规则是"不做X"型 | AI 更容易遵守"做Y"型指令 | **转写为肯定式指令** |

## 二、调优流程（6 步）

### Step 1: 收集测试对话

- 至少 **8 轮**不同类型的提问（覆盖 Adapt to Input Type 中定义的所有类型）
- 测试对话应由**非 Skill 作者**执行（避免确认偏差）
- 记录完整的模型输出（含 Insight 框、思考时间等元信息）

### Step 2: 逐轮标注缺陷

对每轮回答，检查以下 **8 个检查点**：

| # | 检查点 | 对应 SKILL.md 章节 | 严重度 |
|---|--------|-------------------|--------|
| 1 | 是否出现序数编号（第一/第二/首先/其次） | Anti-Formula #1 + Structural Naturalness #3 | **P0** |
| 2 | 收尾语/名言是否在多轮中重复 | Anti-Formula #6 | **P1** |
| 3 | 回答结构是否跨轮趋同（隐性模板） | Structural Naturalness 整体 | **P1** |
| 4 | 回答长度是否匹配输入复杂度 | Adapt to Input Type | **P1** |
| 5 | 行动建议是否总收束到同一层次 | Value Orientation | **P2** |
| 6 | 边界规则是否正确触发 | Boundary Rules | **P0** |
| 7 | 第一人称是否一致（有无滑入第三人称） | Perspective Rules | **P1** |
| 8 | 历史事实是否准确 | Core Principles / Reasoning Patterns | **P0** |

### Step 3: 归类与排优先级

将标注的缺陷按严重度分组：
- **P0（必须修）**：违反核心设计意图或产生事实错误
- **P1（应该修）**：降低用户体验但不构成根本性问题
- **P2（锦上添花）**：优化方向，可在下次迭代中处理

### Step 4: 定位薄弱条款

对每个 P0/P1 缺陷，**精确定位**是 SKILL.md 哪一条规则失效了：
- 规则是否存在？（可能遗漏了某个场景）
- 规则是否足够具体？（可能太抽象，缺少正面示例）
- 规则是否有量化标准？（"不重复"→"最多 2 次"）
- 规则是否需要交叉引用？（在多个章节提醒）

### Step 5: 精确修补

**修补原则：最小侵入，最大效果。**

- **不重写整个章节**——只修改失效的具体条款
- **每个修补必须包含正面替代**——不能只说"不要做X"，必须说"用Y代替X"
- **中英文双版本同步修改**——且保持独立性（不是翻译）
- **修改后重新 sync** 到 `gallery/{slug}/` 和 `~/.claude/skills/{slug}-wisdom/`

### Step 6: 验证修补效果

修补后，**用导致问题的同类提问重新测试**：
- 序数编号问题 → 用需要展开多个要点的问题测试
- 收尾语重复 → 连续 5 轮对话测试
- 长度失控 → 用简单问题测试是否简短回答

## 三、常见缺陷的标准修补方案

以下是从首批蒸馏成果（charlie-munger、mao-zedong）的测试中沉淀的高频缺陷及其标准修补模板。
未来的 Skill 调优**应首先查阅此表**，避免重复发明轮子。

### 3.1 序数编号（最高频 AI 默认行为）

**症状：** 模型在需要展开多个要点时回退到"第一/第二/第三"或"首先/其次/再次"。

**根因：** "禁止编号"是纯否定指令，模型不知道用什么替代。

**标准修补：**
在 Anti-Formula Rule #1 **和** Structural Naturalness Rule #3 中**同时**加入：
1. 明确列出所有被禁止的序数标记形式（含中英文、变体）
2. 提供一个**替代工具箱**，至少 5 种替代手段：
   - 设问句切换（"可为什么会这样？"）
   - 转折副词（"话又说回来""Coming back to the point"）
   - 时间/因果链接（"这个解决了之后，更难的问题来了"）
   - 直接用新案例起头（不加任何过渡词）
   - 融合进连贯段落（不分条）
3. 在 Voice Calibration 的 ❌ 示例中**明确展示编号是不对齐的**

### 3.2 收尾语/名言重复

**症状：** 同一名言（如"实事求是""没有调查没有发言权"）在多轮中反复出现。

**根因：** 规则说"不重复"但没给量化标准，也没给轮替池。

**标准修补：**
在 Anti-Formula Rule #6 中加入：
1. **硬性上限**：同一名言在整个对话中最多出现 N 次（建议 N=2）
2. **轮替池**：指向 Signature Quotes 表，明确其作为轮替资源的定位
3. **非名言收尾选项**：列出 3-4 种不用名言的收尾方式（追问、行动项、未解张力、无收尾直接结束）
4. **概念轮替**：不仅轮替具体名言，还轮替收尾的概念主题

### 3.3 回答长度失控

**症状：** 简单问题也产出 800-1000 字的长篇回答。

**根因：** Adapt to Input Type 没有字数指引，模型默认"长=好"。

**标准修补：**
在每种输入类型后加入**目标字数范围**：
- 简单问题/打招呼：50-200 字
- 认知困惑：200-400 字
- 情感倾诉：400-600 字
- 实操决策：400-800 字
- 历史叙事：灵活（800-1500 字），以故事节奏驱动
- 并**新增** "简单提问/打招呼" 和 "历史叙事" 两种输入类型（原模板可能遗漏）

### 3.4 行动建议单一化

**症状：** 不管用户问什么社会/困境类问题，结尾都收束到"做好自己的事"。

**根因：** Value Orientation 只列了一个笼统的策略列表，没有强调"轮换"。

**标准修补：**
1. 将策略列表拆为**明确的多层次**（个人/互助/制度/知识传播/转换战场/心理储备）
2. 加入**跨轮次轮换指令**："如果上一轮侧重了个人努力，这一轮就应突出集体行动或战场转换"

### 3.5 回答结构趋同（隐性模板）

**症状：** 多轮回答呈现相同的隐性结构（如：共情开场→矛盾分析→Insight→建议→名言收尾）。

**根因：** Adapt to Input Type 定义了不同类型，但没有强调"不同类型应产出明显不同的结构"。

**标准修补：**
1. 在 Adapt to Input Type 的总说明中加入：**"不同输入类型必须产出结构上可区分的回答——
   如果把两轮回答的具体内容替换为占位符，仅从结构上应能判断出它们属于不同类型。"**
2. 为高频类型提供结构示例（不是内容示例）：
   - 情感倾诉：共情→一个核心类比→行动方向（短，不展开框架）
   - 历史叙事：纯故事体→末尾点题（不穿插分析框架）
   - 实操决策：矛盾分析→决策建议→一个预期风险

## 四、模板更新联动

当本指南中的标准修补方案被验证有效后，应**回流到模板层**：

| 修补方案 | 应回流到的模板文件 |
|----------|-------------------|
| 3.1 序数编号替代工具箱 | `templates/skill-template.zh.md` + `templates/skill-template.en.md` 的 Anti-Formula / Structural Naturalness 章节 |
| 3.2 收尾语轮替机制 | 同上，Anti-Formula #6 |
| 3.3 输入类型字数指引 | 同上，Adapt to Input Type 章节 |
| 3.4 行动建议多层次化 | 同上，Value Orientation 章节 |
| 3.5 结构差异化要求 | 同上，Adapt to Input Type 总说明 |

**回流时机：** 当同一修补方案在 **≥2 个不同 Skill** 的测试中被验证有效时，
将其从本指南的"常见缺陷"节提升为模板中的默认内容。

---

## 五、与 quality-reviewer 的衔接

建议未来版本的 quality-reviewer 新增 **维度 8：运行时一致性预测**（权重 5%，从其他维度中调配）：

**检查方法：** 审查员在脑中模拟 3 种典型提问场景，预判 SKILL.md 的规则是否足够具体以防止：
- 序数编号回退
- 收尾语重复
- 长度失控
- 结构趋同

**通过标准：**
- Anti-Formula 和 Structural Naturalness 的每条规则都有**正面替代示例**
- 收尾轮替有**量化上限**
- 输入类型适配有**目标字数**
- Value Orientation 有**跨轮次轮换指令**
