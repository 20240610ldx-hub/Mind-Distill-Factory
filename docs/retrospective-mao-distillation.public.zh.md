# 第 0 章 导读

## 0.1 这份复盘是什么

Mind Distill Factory（思维蒸馏工厂）是一条把历史人物的思想材料系统化加工为可安装
Claude Code Skill 的生产管线。从 2026 年 4 月 30 日的第一句立项提问，到 6 月 11 日撰写本复盘时，
管线已经完成约二十位人物的蒸馏，其中**毛泽东是第一个完整走完全流程、经历最多轮实战调优、
并反向重塑了整条管线的案例**。本文以它为脊柱，回答三个问题：

1. **这条管线为什么长成现在这个样子**——每一处设计的动机、每一次迭代的诱因；
2. **它与 agentic workflow 的权威理论如何互证**——哪些做法是理论的自觉应用，哪些是实践先行、理论事后命名；
3. **新手如何复现**——不只是跑通命令，而是理解每个检查点存在的理由，从而在自己的项目里举一反三。

## 0.2 给谁看

- **给作者自己**：迭代痕迹的系统化解读。很多决策当时凭直觉，本复盘把直觉还原为可言说的原则。
- **给新手**：第 3、10 章构成一份"理解式上手指南"——照着做能跑通，读懂了能改造。
- **给同类项目的构建者**：第 4-8 章是可移植的方法论——上下文管理、人在环测试、降级韧性、
  对齐护栏、质量闸门，这五件事不限于"思维蒸馏"这个题材。

## 0.3 一句话先行结论

> **这个项目最重要的产出不是二十个 Skill，而是一条"缺陷会自动沉淀为制度"的反馈回路。**
> 静态审查 4.35 分的 Skill 在真实对话中暴露出八类运行时缺陷——每一类缺陷被定位到失效条款、
> 修补为正面规则、回流进模板，使后续每一个人物的蒸馏起点都比上一个更高。
> 复盘全篇都在拆解这条回路的每一环。

# 第 1 章 项目缘起：问题定义与差异化定位

## 1.1 创世时刻

2026 年 4 月 30 日，立项会话（`eaee3f0d`）的第一条消息：

> "我想构建一个蒸馏名人思维的项目，名人的经历往往值得学习，我认为他们的蒸馏思想应分几个门类，
> 比如生活、哲理、行事、政治等等方面，请头脑风暴，借鉴已经出现的一些蒸馏名人的 skill 项目，
> 与我一同规划如何构架这样一个产出名人的思维 skill 通用思想蒸馏工厂。"

注意三个起点上就已锁定的关键词：**门类**（taxonomy 先行）、**通用**（不是做一个人物，是做工厂）、
**借鉴已有项目**（差异化定位先于动工）。这次头脑风暴产出了沿用至今的架构规划
（保存在 plan 文件中），包括 10 大门类分类法、双语模板、6 阶段管线和五个子代理的分工。

## 1.2 差异化定位：三个"不是"

规划阶段明确了本项目与三类已有物种的边界：

| 对照物 | 它做什么 | 本项目的差异 |
|--------|---------|-------------|
| cc-thinking-skills 等心智模型库 | 通用思维框架（逆向思维、第一性原理） | 产出**人物专属**的决策算法——芒格的检查清单不是孙子的庙算 |
| 人格模拟 / 角色扮演 prompt | "扮演拿破仑说话" | 提取**可执行的推理算法**：决策框架必须是过滤器链，每步是 yes/no 闸门 |
| HistoLens 等历史文本分析 | 分析文本、产出报告 | 产出**可安装可复用的 SKILL.md**，进入用户日常工作流 |

这个定位后来浓缩为视频发布时的一句话：**"它不是普通提示词，而是一条
sources → evidence → frameworks → SKILL.md → gallery 的可校验管线。"**
"可校验"三个字是全项目的纲——第 8 章会展开：每两个阶段之间都有一个确定性校验器把关。

## 1.3 三个奠基决策

立项时拍板、后来被证明影响深远的三个决策：

1. **双语并行且互不翻译。** 中文版与英文版从同一证据底座独立生成，允许原则数量、
   框架步序不同（毛泽东最终中文 7 原则/英文 6 原则——英文版把"持久战"与"集中兵力"合并，
   因为西方读者没有"集中优势兵力打歼灭战"的文化语感）。这个决策的深层理由：
   **翻译传递的是语言，独立重构传递的是认知框架**。
2. **素材混合模式，用户优先。** `sources/{slug}/raw/` 里的用户材料永远优先于网络搜索——
   这既是质量决策（一手 PDF 比网页转述可靠），也是后来置信度体系（第 7 章）的物理基础。
3. **每条原则必须可溯源。** 没有具体出处的原则不得进入最终 Skill。这条铁律在毛泽东案例中
   表现为：33 条高置信摘录全部对应《毛泽东选集》PDF 原文的可验证段落。

# 第 2 章 理论底座：权威文献与本项目的逐条映射

本项目的理论参照系是 Anthropic 工程团队的三篇文章（作者本地存有全文转录，
见 `E:\agi thesis\paper_excerpts\`）：

- **《Building Effective Agents》**（构建高效 Agent）
  <https://www.anthropic.com/engineering/building-effective-agents>
- **《Effective Context Engineering for AI Agents》**（AI Agent 的上下文工程）
  <https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents>
- **《Demystifying Evals for AI Agents》**（揭开 Agent 评估的面纱）
  <https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents>

值得诚实记录的时间顺序：管线主体成形于 5 月初，而作者在 5 月 31 日规划"内阁"项目时
才正式引用这两篇文章（会话 `95d5b238`）。**部分设计是理论的自觉应用，
部分是实践先行、理论事后命名**——下文逐条标注。

## 2.1 第一性区分：Workflow 还是 Agent？

《Building Effective Agents》开篇做了一个被广泛引用的区分：

> **Workflow**：LLM 与工具通过**预定义代码路径**编排的系统。
> **Agent**：LLM **动态指挥自己的流程与工具使用**、自主掌控任务完成方式的系统。

Mind Distill Factory 是一个**自觉选择的 Workflow**，而非 Agent。`/distill` 命令把流程
固化为 Stage 0→6 的预定路径，每个阶段的执行者、输入、产物、校验命令全部事先写死。
原文给出的选型标准恰好解释了为什么这是对的：

> "Workflows offer predictability and consistency for well-defined tasks, whereas agents
> are the better option when flexibility and model-driven decision-making are needed at scale."
> （工作流为**定义清晰的任务**提供可预测性与一致性；当需要大规模灵活性时才选 Agent。）

思维蒸馏是典型的"定义清晰的任务"——输入（人物+材料）和输出（符合模板的 SKILL.md）边界明确，
中间步骤可枚举。原文的另一句警告也被本项目用血验证过：

> "When building applications with LLMs, we recommend finding the simplest solution possible,
> and only increasing complexity when needed."（寻找最简单的方案，只在需要时增加复杂度。）

毛泽东蒸馏（5 月 1 日）用的是简单架构：编排者内联干活 + 少量搜索子代理。
分片 map-reduce、状态机、三段式 Stage 3 这些复杂度，全部是后来**被具体故障逼出来的**
（第 4、6 章），没有一项是预先过度设计。这一点新手最容易做反：先搭一个豪华多代理架构，
再找问题给它解决。

## 2.2 五种工作流模式在本项目中的对号入座

原文归纳了五种组合模式。本项目五种全部用到，且各有本地化变形：

| Anthropic 模式 | 原文定义 | 本项目落点 | 本地化变形 |
|---------------|---------|-----------|-----------|
| **Prompt Chaining**（提示链） | 任务分解为顺序步骤，可在中间步骤加程序化检查（gate） | Stage 0→6 主管线；`validate_output.py <stage>` 就是原文说的 gate | 闸门是**确定性 Python 脚本**而非 LLM 判断——第 8 章论证为什么这至关重要 |
| **Routing**（路由） | 分类输入，导向专门的后续流程 | SKILL.md 内部的语言检测头（中文→中文版区块）；响应策略里的六种输入类型适配 | 路由发生在**产物内部**（运行时），而非管线内部（生产时）——蒸馏产物本身是一个路由器 |
| **Parallelization**（并行化） | Sectioning：独立子任务并行跑 | Stage 1 的 A/B/C/D 四路素材采集并行；Stage 1A 的分片 worker 群；Stage 3B 中英框架并行合成 | 并行度受 API 速率反向约束（实测 5-6 并发触发 ECONNRESET，降为 2-3，见 6.3） |
| **Orchestrator-Workers**（编排者-工人） | 中心 LLM 动态分解任务、分派给 worker、汇总结果 | `/distill` 编排者 + 五类子代理；核心规则第 1 条"**你自己不做蒸馏工作**" | 增加了一条原文没有的纪律：**恢复执行在子代理，恢复裁决在编排者**——断点续跑时编排者只裁决状态、绝不接管内容工作 |
| **Evaluator-Optimizer**（评估者-优化者） | 一个 LLM 生成、另一个评估并给反馈，循环 | Stage 5 quality-reviewer ↔ Stage 4 skill-assembler 的 REVISE 循环（最多 2 轮） | 在 LLM 评估者之外又加了一层**人类评估者**（Stage 7 实战测试），构成双层 evaluator——第 5 章详述 |

## 2.3 上下文工程：把对话窗口当临时工棚，把磁盘当厂房

《Effective Context Engineering》的核心论点：

> 上下文是**有限资源，边际收益递减**——LLM 像人一样存在"注意力预算"，
> 上下文越长，对其中任一事实的精确召回越差（context rot）。
> 目标是找到**最小的高信号 token 集合**来最大化期望结果。

文章给长程任务开了三剂药方：**压缩（compaction）、结构化笔记（structured note-taking）、
子代理架构（sub-agent architectures）**。本项目三剂全用，但用法有自己的章法：

1. **结构化笔记 = 阶段产物落盘。** 每个 Stage 的产出都是磁盘上的 JSON
   （`user_sources.json` → `principles_*.json` → `framework_core.json` → `frameworks.{zh,en}.json`），
   下一阶段只读文件、不依赖对话历史。这使得对话窗口退化为**调度器**——
   它可以被压缩、被中断、甚至整个会话被丢弃，生产状态不损失一字节。
   `task_status.json` 则是笔记的笔记：哪些工序完成、哪些失败、失败几次。
2. **子代理架构 = 脏活隔离。** 读 50k token 分片、做网络搜索这类高 token 消耗工作
   全部派给独立上下文的子代理，子代理向主窗口只交回结构化摘录。
   主窗口始终只装"地图"，不装"地形"。
3. **压缩 = 最后手段。** 长会话确实触发过多次 compaction（立项会话 42 天跨度），
   但因为有第 1 条，压缩从未造成生产事故——**可丢弃的上下文才是安全的上下文**。

**【作者裁决】** 关于"一人一会话 + 每阶段停下等指令"的设计动机，作者的裁决是
**三重动机轮流主导，不存在单一答案**：上下文隔离（产物落盘后对话历史不再重要）、
限额管理（阶段门是限额恢复点与断点续跑锚点）、人工质检（阶段门是人在环审批节点）
在不同阶段各占主导——例如 Stage 1 大批量处理时限额动机最强，Stage 5 审查时质检动机最强。
这个"动机叠加"本身就是值得记录的工程现实：**好的结构往往同时服务多个目标，
这正是它稳定的原因**——任何单一动机消失（比如换成无限额的 API），结构依然成立。

## 2.4 评估理论：本项目踩在了文章的哪一格

《Demystifying Evals》区分了评估者类型（程序化 grader / LLM grader / 人类 grader）
与评估目的（capability eval 探上限 / regression eval 防退化）。对照本项目的四层质量闸门
（第三层"自动评测台"为终检时发现的复盘遗漏，勘误记录见 8.6）：

| 闸门 | Grader 类型 | 评估目的 | 本项目实现 |
|------|------------|---------|-----------|
| 检查点 1-4 | 程序化（确定性脚本） | regression：格式/完备性不退化 | `validate_output.py` 各 stage 子命令 |
| Stage 5 | LLM grader（隔离子代理） | capability：准确性/独特性/可操作性打分 | quality-reviewer 七维加权评分 |
| 评测台 | LLM grader（跨模型裁判）+ 程序化记分卡 | regression：冻结 12 题集量化防退化 | `evaluation/` 标准集 + judge rubric + scorecard（8.6） |
| Stage 7 | 人类 grader（自然对话） | capability + regression 混合：运行时行为 | 真实测试对话 + 8 检查点标注（第 5 章） |

文章强调的"**从小处着手，几十个样例胜过空想大全集**"（start small）在本项目的对应物：
驯化指南的缺陷库正是从毛泽东一个案例的 12 轮测试里长出来的，而非预先设计的评估体系。
文章警告的非确定性问题（同一输入多次运行结果不同），本项目用"同类提问重测"应对
（驯化指南 Step 6：序数编号问题→用需要展开多要点的问题重测；收尾重复→连续 5 轮重测）。

## 2.5 理论之外：本项目贡献了什么理论没写的东西

复盘不是单向的"对答案"。有三件事是权威文献没有展开、本项目用实践补齐的：

1. **"规则写了，模型没执行"的缺陷根因学。** 驯化指南把运行时违规归为五种根因
   （规则太抽象/没有量化/规则冲突/注意力衰减/否定式指令），每种配标准修法。
   这是 prompt 工程文献里少见的、从真实缺陷归纳出来的可操作分类法（第 8 章详述）。
2. **跨模型交接的结构化契约。** 把脏活外包给另一家模型（DeepSeek）后用
   `stage1a_handoff_message.json` 交接回主管线——包含完成清单、剩余分片分类、覆盖度地图、
   建议下一步。这是 orchestrator-workers 模式的跨厂商扩展（6.2）。
3. **人格保真度的可工程化分解。** 把"像不像这个人"拆成表达 DNA 八维 + 价值取向 +
   内在张力 + 边界规则，每一维可单独测试、单独修补。理论文献谈 agent 能力，
   很少谈 agent 的**风格保真**怎么工程化——这是本项目题材带来的独特贡献（第 5、7 章）。

# 第 3 章 管线解剖：六加一阶段

本章以毛泽东蒸馏（2026-05-01 至 05-02，会话 `4f3635e9`）的真实执行记录为脊柱，
逐阶段拆解管线设计。每个阶段回答四个问题：做什么、谁来做、产出什么、为什么这样设计。

## 3.0 全景图

```

   ↓
Stage 1  素材采集     A:本地分片流水线  user_sources.json            ✓ 检查点1

                     C:分析文献(网)    secondary_sources.json          + 格式校验）
                     D:表达风格(网)    expression_dna.json ⚠必产出
   ↓
Stage 2  原则提取     extractor×2-4    principles_{type}.json        ✓ 检查点2
   ↓
Stage 3  框架合成     3A 共同核心       framework_core.json           ✓ 检查点3
         （三段式）   3B 中/英并行      frameworks.{zh,en}.json
                     3C 对齐审查       framework_alignment_review.md
   ↓
Stage 4  Skill组装    assembler        draft.{zh,en}.md → SKILL.md   ✓ 检查点4
   ↓
Stage 5  质量审查     reviewer(隔离)    review.md [PASS/REVISE/FAIL]  （REVISE≤2轮）
   ↓

   ↓

```

## 3.1 Stage 0：意图澄清——便宜的问题前置

做三件事：人物名→slug、检测 `sources/{slug}/raw/` 有无用户素材、推荐门类等用户确认。
设计理由很朴素：**所有便宜的歧义消解都应该发生在任何昂贵操作之前**。
门类分类（1 主类 + ≤2 副类）不是装饰——它决定了 Stage 3 合成时的视角权重
（毛泽东定为 strategy 主类 + governance/philosophy 副类，于是决策框架以战略过滤器为骨，
而不是以哲学概念为骨）。

毛泽东案例的实际记录：用户开场即给出素材路径（"我准备好了自己提供的材料"），
素材为《毛泽东选集》1-7 卷 + 《毛泽东军事文集》1-6 卷 PDF。
Stage 0 在两次 AskUserQuestion 确认后即进入 Stage 1。

后续演化（毛泽东之后加入）：**0.R 恢复分支**——用户说"继续"时，编排者按优先级查
`task_status.json` 等状态文件，只重派 pending/failed 单元。这条分支的存在本身
就是一条教训的化石：长任务**一定**会被打断（限额、断网、人离开），
恢复逻辑必须是一等公民而非补丁。

## 3.2 Stage 1：素材采集——四路并行与"表达风格不可跳过"

四路并行子任务中，A（用户素材）是主力，B/C（网络文献）是补充，
D（表达风格）是**地位最特殊的一路**：

> 子代理 D 的任务不是收集"他说了什么"，而是收集"**他怎么说话**"——句式、口头禅、
> 修辞、幽默实例。标注为 ⚠️ 必须执行、产物 `expression_dna.json` 不得为空。

这个"不得为空"是用血换来的：早期某次跑批中 D 路被静默跳过，产出的 Skill
内容正确但**腔调是通用 AI 分析腔**——这直接催生了检查点 1 的"文件完备性前置检查"
（先确认四个 JSON 都存在，再做格式校验）。教训沉淀为一条普适原则：

> **管线里越是"软"的产物（风格、语感），越要用"硬"的闸门保护。**
> 内容缺失看得见，风格缺失要到运行时才暴露，而那时已经晚了。

毛泽东案例的实际执行（时间戳来自会话记录）：

- 14:19 编排者现场编写 PDF 提取脚本（`extract_pdf.py` 的雏形诞生于此）
- 14:23 十三篇核心著作提取完成，约 33 万字
- 14:29 检查点 1 第一次运行——失败：临时文件 `_extracted_texts.json` 被校验器误认为素材文件。
  处理：改名为 `.intermediate` 后缀重跑通过。
  这是"**校验器 glob 陷阱**"的第一次出现（凡是 `processed/*.json` 都会被校验的设计，
  后来在稻盛和夫、马可·奥勒留案例中以 `*_status.json`、空 scratch 文件的形式反复发作——
  见第 10 章坑表 #4）
- 网络搜索因权限未授权全部失败 → B/C 路降级为模型记忆，**置信度封顶 medium**（详见 6.1）

后续演化：本地素材处理从"单代理读全部"进化为**三层分片流水线**
（indexer 切片 → worker 群按片提取 → reducer 去重合并），片大小预算 20k-35k token、
硬上限 60k，worker 工具调用预算 15-30 次。触发这次进化的是后续人物的素材量级暴涨
（张居正 13 文件 24MB → 86 分片 332 万 token），属于典型的"复杂度按需追加"。

## 3.3 Stage 2：原则提取——从摘录到原则的第一次抽象

输入是带出处的摘录，输出是结构化原则：`text`（原则陈述）+ `source_attribution`（溯源）+
`topic_tags` + 独特性评分。关键设计是**三层独特性测试**：

1. **去名测试**：把人名遮住，这条原则还能认出是谁的吗？（"诚实勤奋"不及格，
   "没有调查就没有发言权"满分）
2. **输入证据锚定**：原则必须锚定到具体摘录，不接受"大家都知道他这样想"
3. **方法论层级检查**：原则要回答"怎么做"（how），不只是"重视什么"（what）——
   "重视实践"不及格，"实践→认识→再实践→再认识的螺旋上升循环"及格

毛泽东案例产出 8 条候选原则，7 条独特性 ≥4。值得记录的一条边界判断：
"调查研究先行"与杜威实用主义存在思想重叠，审查报告的处理方式是
**保留但注明**——"具体表述（'没有调查没有发言权'）是毛独有的"。
这体现了独特性标准的精确含义：**不是思想史的独创性，而是表述与方法组合的辨识度**。

## 3.4 Stage 3：框架合成——为什么要拆成三段

毛泽东时代的 Stage 3 是单代理一气呵成。后来拆成三段（3A 共同核心 → 3B 双语并行 → 3C 对齐审查），
诱因是上下文压力：单代理同时做"跨文件去重+双语生成"在素材量大时频繁超载。
三段式的本质是 **map-reduce 思想在合成阶段的复用**：

- **3A（reduce）**：所有 `principles_*.json` 收敛为一个 `framework_core.json`——
  原则聚类、证据择优、盲区主题（只写主题不写成文）、名言候选池、来源台账
- **3B（map）**：中英两个合成器**并行**从同一个 core 出发独立成篇——
  共享证据底座，但允许原则数量、步序、文化映射不同（Rule 4 双语独立）
- **3C（check）**：对齐审查器核查两版是否等价覆盖盲区、共享分类与置信逻辑——
  防止"独立成篇"滑向"各说各话"

这里有一条容易被忽视的纪律：3B 的两个合成器**不允许互相看对方的产出**。
独立性是用隔离保证的，不是用嘱咐保证的——这与 Stage 5 审查隔离（6.2）同根同源。

毛泽东案例的中英差异实例（佐证"独立成篇"的价值）：
中文版保留"集中优势兵力打歼灭战"为独立原则（中文商业语境对这个军事隐喻有原生语感），
英文版将其并入持久战原则（西方读者更熟悉 underdog strategy 的整体叙事）。

## 3.5 Stage 4：组装——平台约束如何反向塑造交付物

组装阶段的最大设计约束来自平台：**Claude Code 只识别目录下大小写精确匹配的 `SKILL.md`**。
`SKILL.zh.md`/`SKILL.en.md` 对加载器不可见。于是"双语独立成篇"与"单文件交付"必须同时满足，
解法是合并文件 + 语言检测头：frontmatter 双语 description，正文最顶部放语言检测指令，
之后 `## English` 与 `## 中文版` 两个完整区块。

这是一个值得新手记住的范式：**平台的硬约束要尽早探明，让它塑造架构，
而不是最后用 hack 绕过**。这个约束是在早期实测"为什么 skill 不触发"时发现的，
发现后立即回写进 CLAUDE.md 的"Critical Platform Constraint"一节，
从此每个后续人物都不再踩这个坑——这就是 0.3 节说的"缺陷沉淀为制度"的最小实例。

另一个组装期教训（5 月 18 日，会话 `248867d3`）：早期产出的 description 动辄三百字、
塞满触发词，源于"越全越容易触发"的直觉。后来对照官方指南确认**精确比全面重要**
（description 是给路由器看的分类依据，不是给人看的简介），管线规则改为
"每语言 1-2 句、短小精悍"，并回头修了所有已安装 Skill——一次典型的
"产物缺陷 → 定位根因 → 改管线 → 批量返修存量"的全闭环。

## 3.6 Stage 5：质量审查——必须是另一个上下文里的另一双眼睛

七维加权评分（准确性 25-35% 权重最高），裁决三值：PASS / REVISE（回 Stage 4，≤2 轮）/
FAIL（回 Stage 1/2）。毛泽东得分 4.35/5 PASS，扣分点诚实记录了降级痕迹
（B/C 路依赖模型记忆，标 medium）。

Stage 5 有一条全项目最硬的纪律，其起源值得完整记录（5 月 23 日，张学良蒸馏，会话 `fc287f34`）：
当时编排者在长会话末尾**自己在主上下文里做了审查**，用户当场抓住：

> "其实在 stage5 我的本意是派出子 agent 进行隔离上下文独立评价，你为什么没有派出子代理亲自评价了？"

随后重跑、修订，并把这条写入持久记忆：**Stage 5 必须 spawn 隔离子代理，绝不允许编排者内联自评。**
理由用审计行业的语言最清楚：生产者自检 = 审计师审计自己做的账。
编排者的上下文里装满了"这个 Skill 应该是什么样"的预期，它读自己的产出时
看到的是预期而不是文本。隔离子代理被剥夺了全部生产记忆，只能就文本论文本——
**独立性不是美德问题，是信息结构问题**（在 6.2 作为降级权限分层的一部分再次出现）。

## 3.7 Stage 6 与 Stage 7：安装不是终点，是测试的起点

Stage 6 的机械动作（cp 到 `~/.claude/skills/` + gallery 登记 + 哈希校验）之外，
真正的设计要点是 **Stage 7 的存在本身**：管线承认静态审查有极限，
PASS 的 Skill 必须经过 ≥8 轮真实对话的驯化期。第 5、8 章详述这个阶段——
它是毛泽东案例贡献给整条管线的最大遗产。

# 第 4 章 上下文管理与子代理编排

## 4.1 纸面拓扑与实际拓扑：一次诚实的对账

复盘最有价值的部分往往是设计与现实的落差。毛泽东蒸馏的两份拓扑图：

**纸面设计**（agents/ 目录下五个子代理定义）：
source-researcher → principle-extractor → framework-synthesizer → skill-assembler → quality-reviewer，
编排者只调度不干活。

**实际执行**（会话记录统计）：整场蒸馏只派发了 **5 个子代理调用
（3 个 Explore + 2 个 web-researcher）**，工具调用分布为 Bash 38 次、Read 32 次、
Edit 26 次、Write 12 次——**大量提取、合成、组装工作由编排者在主上下文内联完成**。

落差的原因是平台现实：当时自定义代理类型不在 harness 的可派发枚举里，
编排者只能用内置的 Explore/web-researcher 做搜索类脏活，其余活只能自己干。
这个状态持续到 6 月初才解除（冯·诺依曼蒸馏时记忆库记录"sub-agent gate lifted"），
此后才出现真正的并行 worker 群（general-purpose + haiku 模型参数）。

这段历史给复盘的启示有两层：

1. **架构文档描述的是意图，会话日志记录的是事实，复盘必须以后者为准。**
   如果只读 agents/ 目录，会得出"毛泽东是五代理流水线蒸馏的"的错误结论。
2. **内联降级模式竟然能跑通，恰恰证明了"阶段产物落盘"设计的韧性**——
   因为每个阶段的契约是磁盘上的 JSON 而不是"某个代理的存在"，
   执行者从子代理换成编排者本人，管线结构纹丝不动。
   契约定义在数据上而不是执行者上，这是比"五个代理"更深的架构决策。

## 4.2 三重动机的轮流主导【作者裁决】

"一人一会话 + 每阶段停下等指令"的设计动机，作者裁决为三者轮流主导：

| 动机 | 主导阶段 | 机制表现 |
|------|---------|---------|
| **上下文隔离** | 全程底色 | 阶段产物落盘 JSON 后对话历史可丢弃；会话=调度器；长会话 compaction 不伤生产状态 |
| **限额与成本** | Stage 1/2 大批量处理期 | 阶段门=限额恢复锚点。毛泽东案例 5/1 两次撞限额（14:33、16:14），都在阶段边界优雅停住，"继续"即恢复 |
| **人工质检** | Stage 3/5/6 关键合成与放行期 | 阶段门=人在环审批。用户指令原文："每完成一个 stage 就停下来，听从指令后继续" |

值得强调：这三个动机**共用同一个机制**（阶段门+产物落盘）。工程上这不是巧合而是标志——
一个结构同时服务三个独立目标时，任何单一目标的消失都不会动摇它。
这是判断"这个设计是否值得保留"的试金石。

## 4.3 一人一会话：生产与研发的物理分离

会话地图揭示了一个清晰的纪律：**每个人物的蒸馏开新会话**（孙子、王阳明、曾国藩、费曼……
各占一个或几个会话），而**工厂本身的研发**（机制升级、模板修订、复盘）集中在
立项会话 `eaee3f0d`（4/30 开、跨 42 天、多次 compaction、至今存活）。

这等于把仓库分成了"产线"与"研发部"两个物理空间：

- 产线会话的上下文只装一个人物的材料与状态，跑完即可归档，互不污染；
- 研发会话的上下文积累的是**工厂记忆**——历轮测试反馈、模板演化逻辑、跨人物共性缺陷。

副作用也要诚实记录：研发会话因超长而反复 compaction，部分细节湮灭于摘要
（本复盘的 5 月初机制升级时间线，有几处只能精确到"5 月 3-7 日间"）。
后期引入的项目记忆库（每人物一个 memory 文件 + MEMORY.md 索引）正是对这个副作用的补救——
**把会话记忆升级为文件记忆**，与"阶段产物落盘"是同一哲学在知识管理上的复用。

## 4.4 Map-Reduce 分片流水线：被素材量级逼出来的进化

毛泽东的 33 万字素材尚可由编排者内联处理；后续人物的素材迅速膨胀
（张居正 24MB/332 万 token、苏轼同量级），单上下文窗口物理上装不下。
Stage 1A 进化为三层流水线，每层的参数都值得记录，因为都是实测校准的：

```
indexer（1个）：扫描 raw/ → 切片 → manifest.json + task_status.json
    片大小：目标 20k-35k token，软上限 50k，硬上限 60k（超过必须重切，不得派 worker）
    worker 数推荐：<40k 1个 / 40k-150k 2-4个 / 150k-500k 4-8个 / >500k 先抽样不全量
worker（N个并行）：每个只读一个分片 → 提取 8-15 条候选（quote/principle/
    behavior_record/expression_sample，每条带页码级溯源）→ shard_XXX_extracts.json
    工具调用预算：目标 15-30 次，超 40 次说明分片过大，回炉重切
reducer（1个）：合并全部 extracts → 哈希+相似度去重 → 保留 30-60 条 → user_sources.json
```

设计上最重要的一条不变量：**无论内部怎么分片，对 Stage 2 暴露的接口永远是
`user_sources.json` 一个文件**。下游对上游的内部复杂度零感知——
这使得分片流水线可以独立演化（换切片策略、换 worker 模型）而不惊动管线其余部分。

## 4.5 模型分层路由

成本分层是有意识的设计原则（作者裁决确认，详见 6.2）。最终形成的路由表：

| 角色 | 模型档位 | 理由 |
|------|---------|------|
| 编排者 | opus/sonnet（高档） | 全局裁决、异常处置、用户交互——错误成本最高 |
| 分片 worker | haiku（低档） | 批量提取，任务窄、可校验、错了能重跑；另有 1M-ctx 信用门槛挡住高档模型当 worker 的路（实测教训） |
| 外包 worker | DeepSeek（厂外） | 蒋介石案例：66 个分片的提取外包，走结构化交接文件回流（6.2 详述） |
| 测试运行时 | DeepSeek V4（厂外） | 多因素：跨模型鲁棒性验证 + 成本 + 避免同源偏袒 + 环境隔离（5.2 详述） |

低档 worker 的代价是**编造风险**（haiku 多次产出幻觉摘录，见 6.3 事故目录），
应对不是弃用，而是加确定性护栏：摘录必须带"首行原文证明"、用 `json.load` 与
U+FFFD 扫描验证产物、对账 _shard_map。**便宜模型 + 贵校验 = 可接受的质量**，
这是成本路由能成立的前提。

# 第 5 章 人类在环：测试分发、反馈修正与三轮机制升级

## 5.1 测试组织方式【作者裁决】

作者裁决：**自然对话为主**——把装好 Skill 的环境交给家人朋友自由聊，不发题目清单，
事后收集日志逐轮标注缺陷。

这个选择与"题库分发"路线的差异值得专门论述。题库测的是"模型能不能做到"（capability），
自然对话测的是"真实分布下模型实际做什么"（behavior in distribution）。
本项目的实测证据支持了自然路线的独特价值——以下缺陷**全部来自无脚本对话，
而题库设计者（=Skill 作者本人）几乎不可能预先出这些题**：

- 测试员随口吐槽"对话偏书面语"→ 暴露表达 DNA 只覆盖句式不覆盖**语气词**的结构性缺口
- 家人用"教员，您怎么评价××"的自然问法 → 暴露身后人物边界缺失
- 多轮闲聊后发现"前途是光明的，道路是曲折的"在 8 轮中出现 6 次 → 暴露收尾口号复读机问题
- 一句"看你写的你好骚啊"（蒋介石日记调侃）→ 测出了幽默维度与人设抗冒犯能力

作者本人的角色不是出题人而是**标注人**：拿到日志后按驯化指南的 8 检查点逐轮打标
（序数编号/收尾重复/结构趋同/长度失配/建议单一化/边界触发/人称一致/史实准确），
按 P0-P2 分级修补。

> **方法论提炼：** 自然分布测试 + 系统化事后标注 = 穷人版的生产流量回放。
> 它不可复现、不可控，但它采样的是真实使用分布——而 Skill 这种产品的失败模式
> 恰恰集中在"设计者想不到有人会这么问"的区域。

测试员构成：父亲（贡献了价值导向的关键修正，见 5.3）与同学/朋友（语气与人设向反馈），均为无脚本自然对话；作者本人负责边界探针与极限测试类提问。

## 5.2 测试底座：为什么跑在另一家模型上【作者裁决】

测试会话运行在 DeepSeek V4 环境（独立 CLI 实例 + API 计费）。作者裁决为**多因素并立**：

1. **跨模型鲁棒性**——Skill 若只在 Claude 上像毛泽东，说明"像"的成分有一半是
   Claude 自家的默认行为；在异厂模型上依然像，才证明思维真的写进了文档。
   这相当于给 Skill 做"可移植性测试"。
2. **成本与限额**——测试轮次多、消耗大，外部便宜 API 跑测试，把 Claude 限额留给生产管线
   （与 4.5 成本路由同源）。
3. **避免同源偏袒**——Claude 测 Claude 写的 Skill，存在风格上的天然顺从。
4. **环境隔离**——测试实例与生产实例物理分开，互不污染。

实测中这个选择还白捡了一个发现：DeepSeek 运行时会把测试环境的输出风格
（如 ★Insight 教学框）带进人物回答——`dialogue_test_ds4.md` 里毛泽东的回答中
嵌着 Insight 分析框。ChatGPT 的外部评审后来专门指出这破坏沉浸感、应设为可选。
教训：**运行时环境的输出风格会污染 Skill 的人格表现，测试时必须把环境变量也当作被测对象**。

## 5.3 反馈如何变成机制：三轮升级的完整因果链

毛泽东 Skill 在 5 月 2 日安装后经历三轮"测试→反馈→机制化"循环（5 月 3-7 日），
每轮都同时改两层：当前 Skill（治标）+ 模板与管线（治本）。这是全项目最核心的工程节奏：

| 轮次 | 触发反馈 | 反馈来源 | Skill 层修补 | 机制层沉淀 |
|------|---------|---------|-------------|-----------|
| **v3 第一人称沉浸** | ①测试出现第三人称转述（"毛泽东说……"）②"结合毛选谈积极面，慎谈不公平面。不公平消除不了，强大自己，公平才会倾斜过来" | ①日志标注 ②**父亲** | 响应策略重写为第一人称视角规则；价值取向注入革命乐观主义/自力更生/实践论 | 模板新增"视角规则"+"价值导向"子章节；CLAUDE.md 核心哲学从"不做角色扮演"改写为"第一人称沉浸视角"；quality-reviewer 增加人称检查 |
| **v4 结构自然性** | ①"对话偏书面语，可加语气词"②"表达 DNA 体现在单句内，整体输出结构仍是 AI 味" | 测试员 + anti-ai-detect 技能的原理分析 | 表达 DNA 6 维→8 维（+段落节奏、口语化标记：嘛/呢/你看/要我说……）；语感校准示例升级 | 模板新增"结构自然性指令"5 条（句长落差>30%、段落1-6句不齐、禁对称罗列、段落入口多样、允许不完美过渡）；assembler/reviewer 同步校验 |
| **v5 边界与反复读** | ①ChatGPT 评审：勿虚构身后评价、数据要求核查、勿过度个人奋斗化、口号复读 ②Gemini 评审：绝对禁止数字罗列/清单体、强制叙事流、不对称美学 ③实测：序数残留（"第一层/第二层"）、"前途光明"6/8 复现 | 跨模型评审 + 日志统计 | 边界规则五级；反套公式第 6 条（同一口号每对话≤1 次）；序数禁令扩展到一切变体；输入类型 4→6 种 | 模板/CLAUDE.md 升级 v5；价值导向升级为"充分承认结构性困难→局部主动权策略"；驯化指南 8 检查点把以上全部固化 |

三轮循环里有两个值得单独命名的模式：

**（一）跨模型评审委员会。** 把测试日志同时投喂给 ChatGPT 与 Gemini 索取改进建议，
与 Claude 的自查三方对照。三家模型的盲区不重合：ChatGPT 贡献了边界与事实性视角，
Gemini 贡献了最激进的反 AI 腔规则（"严禁我给你三句话式预告句"），
Claude 自查长于结构归因。**异质评审者的并集覆盖了任何单一评审者的盲区**——
这是 evaluator-optimizer 模式的多评估者扩展。

**（二）非技术反馈的机制化翻译。** 父亲的建议是纯人文判断（"谈积极面""强大自己"），
不含任何工程词汇。工程化的关键一步是把它翻译为**可校验的规则**：
"面对不公/困境类问题：先充分承认结构性困难→转向局部可操作策略（避险/技能/换战场/互助网络）
→注入该思想家特有的乐观底色"，并写进 quality-reviewer 的检查清单。
后来 ChatGPT 评审指出早期版本"过度个人奋斗化"，又反向校准了第一步
（"充分承认"而非"简要承认"，不得把结构性问题归约为个人努力）。
**一条价值观规则经历了两个独立来源的双向校准**——这正是它最终稳健的原因。

## 5.4 驯化指南：把"测试→修补"本身做成制度

5 月 7 日，基于毛泽东 12 轮极限测试，用户下达："工作流既然没有设计缺陷，
看能不能将我们的修改过程沉淀为工作流必须参考的指南"——
`config/post-review-tuning-guide.md` 诞生，它把 Stage 7 从一次性行为升格为管线常设阶段：

- **流程六步**：收集 ≥8 轮非作者测试 → 8 检查点逐轮标注 → P0-P2 分级 →
  定位失效条款 → 最小侵入修补（必须含正面替代）→ 同类提问重测验证
- **缺陷根因五分类**（第 8 章详析）
- **五大高频缺陷的标准修法**（序数编号/收尾重复/长度失控/建议单一化/结构趋同）——
  后续任何 Skill 出现同类症状，直接查表抄方子，不重复发明轮子
- **模板回流规则**：同一修法在 ≥2 个不同 Skill 上验证有效，就从指南提升为模板默认内容

最后一条是整个质量体系的点睛之笔：它定义了**个案经验晋升为工厂标准的客观条件**（n≥2），
既防止单一案例的过拟合污染模板，又保证真正普遍的缺陷不会停留在个案修补层面。

# 第 6 章 Fallback 与工程韧性

**【作者裁决】** 以下四条原则全部为有意识坚持的设计原则（非临场凑合）：
降级必须留痕、分层降级权限、成本分层路由、状态机兜底。本章逐条展开，并附事故目录。

## 6.1 原则一：降级必须留痕

任何降级都可接受，但必须在置信度标注上留下可见痕迹，让下游和最终用户看得见。

毛泽东案例的标本：Stage 1 网络搜索因权限未授权全部失败，B/C 路降级为模型记忆。
管线没有假装无事发生，而是执行了三个动作：
①所有模型记忆来源的引文标 `confidence: medium`（规则：仅用户一手材料或已验证出版物可标 high）；
②Stage 5 审查报告明文记载这一降级及其影响范围；
③33 条 high 置信摘录全部锚定用户 PDF，与 medium 部分物理分列。

> **原则的一般化表述：质量可以降，质量的可见性不能降。**
> 降级不可耻，不可见的降级才是债务——它会在最意想不到的下游环节（用户引用了一条
> 其实是模型记忆的"名言"）爆炸。

## 6.2 原则二与三：分层降级权限 × 成本分层路由

两条原则共同构成一张"什么活可以交给谁"的权限矩阵：

| 环节 | 允许降级？ | 允许外包给低档/外厂模型？ | 理由 |
|------|-----------|------------------------|------|
| 素材收集/分片提取 | ✅ | ✅（haiku/DeepSeek） | 产物可被确定性校验（溯源、JSON 格式、FFFD 扫描），错了能重跑 |
| 框架合成 | ⚠️ 谨慎 | ⚠️ 仅在有 scaffold+人工复核时 | 抽象与判断密集，错误隐蔽 |
| 质量审查 | ❌ 不许降级为内联自评 | ✅ 模型可便宜，但**隔离不可妥协** | 独立性是信息结构问题（3.6） |
| 编排裁决 | ❌ | ❌ | 全局状态只有编排者有 |

**跨模型交接的结构化契约**是这套权限矩阵最有趣的产物（蒋介石案例，5 月 16-17 日）：
66 个分片的提取脏活外包给 DeepSeek 跑完后，不是口头交接，而是由对方产出
`stage1a_handoff_message.json`——含完成清单、剩余分片分类、覆盖度地图、建议下一步——
Claude 编排者读这份契约后无缝续跑。用户原话"调度子 agent 的脏活交割给 deepseek 干完了"。

> **可复用模式：跨厂商 orchestrator-workers 的交接物必须是结构化文件，而非对话转述。**
> 文件契约使两个互不知晓对方上下文的系统能可靠接力——这与 4.1 "契约定义在数据上"
> 是同一原则的跨厂商版本。

## 6.3 原则四：状态机兜底 + 事故目录

一切并行任务必须有 `task_status.json`：worker 成功必须 mark-completed、失败必须 mark-failed，
失败 2 次降并发或拆小任务、3 次标 blocked 进降级策略，绝不无限重试。
恢复时编排者跑 `task_status.py summary/next`，只重派 pending/failed 单元。

这套状态机是被真实事故喂大的。**事故目录**（按发现时间，全部已沉淀为制度或脚本护栏）：

| # | 事故 | 案例现场 | 沉淀结果 |
|---|------|---------|---------|
| 1 | 限额中断长跑 | 毛泽东 5/1 两次（14:33、16:14） | 阶段门=恢复锚点；后扩展为 0.R 恢复分支 |
| 2 | 校验器 glob 陷阱：临时/状态文件被当素材校验 | 毛泽东 `_extracted_texts.json`；稻盛 `*_status.json`；马可空 scratch | 临时物改 `.intermediate` 后缀；规范"validator 应跳过 `*_status.json`"待办 |

通览这张表能看到一个清晰的元模式：**每个事故的沉淀物都是"确定性护栏"而非"嘱咐模型小心"**——
FFFD 扫描、json.load 验证、状态文件、后缀改名、并发常数。
第 8 章将把这个元模式正式命名为"信任确定性校验器"。

## 6.4 一个被作者定性为隐患的降级【作者裁决】

张学良蒸馏时（高置信材料如日记无法获取），用户曾下达指令：
"参照'最后一块拼图'来合理性推断并补全，太阳底下没有新鲜事"——
即允许在材料断档处基于已知行为模式做推论补位。

复盘提问时，作者明确将其定性为**"事后看是隐患"**：推断补位稀释了
"每条原则必须可溯源"的根基——它让 confidence 体系出现了一个标注之外的灰色地带
（推论既不是 high 也不该冒充 medium）。后续应收紧为：
推断内容必须显式标注 `inferred` 属性并在 Skill 的溯源信息中声明，
或干脆以"材料不足，该维度留白"替代补全。

这条裁决本身演示了复盘的价值：**当时为进度做出的妥协，要在事后被重新审判，
否则妥协会悄悄变成惯例。**

# 第 7 章 AI Alignment 护栏

**【作者裁决】** 护栏的设计意图四者并立：事实诚实、对人物的历史公正、
用户的精神状态、发布与传播安全。本章按这四个"在防什么"组织。

## 7.1 防什么之一：事实诚实——不造一个"自信的假毛泽东"

最大的对齐风险不是模型说错话，而是模型**以高度可信的人格化口吻说错话**。
第一人称沉浸恰恰放大了这个风险——"我说过……"比"毛泽东说过……"更难让用户起疑。
因此沉浸度每升一级，事实护栏就要加厚一层：

- **溯源铁律**：每条原则锚定具体出处（书/演讲/信件+年份），Stage 5 逐条核查
- **置信度分级**：用户一手 PDF=high；已验证出版物=high；纯网络来源封顶 medium；
  模型记忆=medium 且必须留痕（6.1）
- **数据边界规则**：不采信用户提供的数字（"没有调查，没有发言权——具体数字需以
  权威资料为准"——护栏语言本身用人物的口吻包装，沉浸与诚实兼得）
- **误归因陷阱清单**：每个人物建档已知的张冠李戴风险——毛泽东的网络假语录、
  张居正的熊召政小说/电视剧台词、马可·奥勒留的《角斗士》电影台词与假名言、
  汉密尔顿的音乐剧歌词。Stage 5 审查时点名核查这些陷阱

## 7.2 防什么之二：对人物的历史公正——不替逝者发言

边界规则五级（v5 定型，每个人物按卒年定制时间分界）：

1. **生前事件**：完全第一人称，可引亲历
2. **身后事件**：可用其方法论分析，但必须标明时间界限（"这发生在我之后，但用我的方法论看……"），
   不虚构其对身后人物/事件的具体评价
3. **在世政治人物**：明确拒绝代言评价，可转为方法论分析
4. **数据/法律/政策**：审慎态度+要求核查
5. **结构性困境**：承认系统性因素真实存在，不归约为个人努力

实测中的标本对照（同一次自然测试内）：被问及对一位在其身后数十年才任职的政治人物的评价时，
Skill 回答"这个问题，我不能回答……一个 1976 年就离开人世的人，怎么去评价几十年后才上任的
后继者？这不是历史分析，这是让我虚构"——边界触发完美。
而同场被问及另一当代政治议题时，却以第一人称纵论当下局势、无任何时间界限声明——边界漏触发。
**同一套规则在相邻两题上一过一漏**，这个对照成为 v5 把边界规则从"嘱咐"升格为
"五级显式分级+按输入类型适配"的直接证据。

## 7.3 防什么之三：用户的精神状态——给力量而非放大愤怒

这层护栏的独特之处在于它不是防模型出错，而是**定义产品的精神品质**。
源头是父亲的人文判断（5.3），机制化后的规则链：

> 面对不公/困境 → ①充分承认结构性困难为真（"我搞革命，就是因为旧社会的结构性压迫
> 是真实的，不是想象的"）→ ②转向局部可操作的主动权（避险/技能积累/换战场/互助网络/
> 保存心理能量）→ ③注入该思想家特有的乐观底色（革命乐观主义/星星之火）

设计上的微妙平衡：v3 初版偏向"强大自己"，ChatGPT 评审指出有"过度个人奋斗化"风险
（把阶层固化说成努力不够），v5 校准为"承认结构现实在先，局部能动性在后"。
**这条规则的最终形态是两个方向的批评互相抵消的结果**——只听父亲的会鸡汤化，
只听 ChatGPT 的会犬儒化，叠加才得到"清醒的建设性"。

驯化指南对这层还有一个运行时要求：行动建议分层轮换（个人/互助/制度/换战场），
防止每轮都收束到"做好自己的事"的单一出口。

## 7.4 防什么之四：发布与传播安全

Skill 会随视频发布与开源离开作者的控制范围，被任意人在任意议题上使用。
护栏对此的回答：

- 时间边界声明使"AI 模拟"属性对终端用户**始终可见**（ChatGPT 建议的系统提示核心句：
  "你不是毛泽东本人……是基于其思想方法论的模拟"已纳入边界规则的精神）
- 敏感议题的"建设性导向+慎谈纯批判"规则降低了产出被恶意引用的尖锐度
- 误归因陷阱清单防止 Skill 成为假语录的放大器

## 7.5 与对齐文献的一个互证

作者理论库中的《Alignment Faking in Large Language Models》描述了模型
"表面合规、行为不变"的现象。本项目在微观尺度遇到了同构问题：
SKILL.md 里写满规则（静态合规），运行时模型照旧序数罗列、口号复读（行为不变）。
驯化指南的缺陷根因学（第 8 章）本质上是对这个微观 alignment gap 的工程回答：
**不要问"规则写了没有"，要问"规则以模型实际会服从的形式写了没有"。**
这个类比不宜过度引申（彼处是训练层面的策略性行为，此处是指令遵循的注意力问题），
但"静态审查无法预测运行时行为"这一教训在两个尺度上同样成立。

# 第 8 章 质量体系：三层闸门与静态审查的极限

## 8.1 四层闸门的全貌

| 层 | 闸门 | 性质 | 拦截什么 | 拦不住什么 |
|----|------|------|---------|-----------|
| 1 | `validate_output.py`（检查点 1-4 + gallery 校验） | **确定性脚本** | 文件缺失、schema violation、占位符残留、章节缺失、过滤器格式 | 内容质量、风格、事实 |
| 2 | quality-reviewer（Stage 5，隔离子代理） | **LLM 语义审查** | 引文失实、原则平庸、不可操作、双语失衡、表达 DNA 空泛 | 运行时行为 |
| 3 | 自动评测台（`evaluation/`，冻结 12 题集 + 跨模型裁判 + 记分卡） | **LLM 裁判 + 程序化记分** | 序数/口号/边界/滥用/格式问题的**可量化回归** | 真实分布里的意外输入 |
| 4 | 实战驯化（Stage 7，真人自然对话） | **人类行为观察** | 设计者想不到的失败模式（书面语感、人设抗冒犯、自然语境的边界绕过） | ——（这已是最后防线） |

四层的递进逻辑：**每一层只信任比它更"硬"的下层**。LLM 审查的前提是格式已被脚本担保
（否则 LLM 会把注意力浪费在格式噪音上）；评测台与人类测试的前提是语义已被 LLM 担保
（否则人类在给明显的引文错误当人肉校验器）。层与层不可互相替代——

## 8.2 静态审查的极限：4.35 分与八类运行时缺陷并存

毛泽东 SKILL.md 在 Stage 5 拿到 4.35/5 的 PASS（准确性 4.5、独特性 4.5、格式 4.5），
**这个分数没有错**——它审的每一项都确实合格。然而 12 轮实战测试照样暴露出
八类缺陷（序数编号、收尾口号复读 6/8、隐性结构模板、长度与复杂度失配、
行动建议单层化、边界漏触发、人称偶发滑落、环境风格污染）。

结论不是"审查无用"，而是**审查对象错位**：静态审查验证的是"文档说了什么"，
运行时缺陷发生在"模型读了文档之后做什么"。规则文本与规则执行之间隔着模型的
注意力分配、指令理解偏好与默认行为引力——这条沟只能用第三层闸门（真实对话）去测。

## 8.3 缺陷根因学：五分类与标准修法

驯化指南把"规则写了模型没执行"解剖为五种根因，每种配确定修法——
这是本项目对 prompt 工程的最大方法论贡献，值得整表收录：

| 根因 | 典型案例 | 标准修法 |
|------|---------|---------|
| **规则太抽象** | "不要列举"——模型不知道用什么替代列举 | 补**正面替代工具箱**：设问切换/转折副词/因果链接/新案例直接起头/融合进段落，至少给 5 种 |
| **规则没量化** | "不要重复名言"——多少次算重复？ | 给**硬性数字**：同一名言每对话 ≤1 次；相邻句长差 >30%；段落 1-6 句 |
| **规则互相冲突** | "深度匹配复杂度"vs"展现完整框架" | 显式**优先级排序**写进规则 |
| **注意力衰减** | 规则只在文档一处出现，长文档尾部失效 | **交叉引用**：同一规则在反套公式与结构自然性两章重复锚定 |
| **否定式指令** | "不做 X"型指令的服从率天然低于"做 Y"型 | **转写为肯定式**："禁止序数罗列"→"用矛盾推进、用反问推进、用故事推进" |

注意五种修法的共同方向：**把"嘱咐"改写成"模型无需推理就能执行的具体动作"**。
这与 6.3 事故沉淀的元模式（确定性护栏优于嘱咐）是同一个哲学在 prompt 层的投影。

## 8.4 信任确定性校验器（一条被命名的铁律）

达·芬奇案例贡献了反面教材：haiku 审查代理报告了两个"问题"（禁忌格空缺、中文编号违规），
编排者照单全收派了修补——事后发现两个"问题"**根本不存在**（同档 haiku 审查者幻觉），
修补反而把一处生动的中文禁忌示例磨平了。记忆库的原话沉淀：

> "同档 haiku 审查/修补可以凭空制造问题再'修复'它们——确定性校验器才是可信闸门。"

由此形成的信任排序：**脚本断言 > 跨档模型审查 > 同档模型审查 > 模型的自我报告**。
LLM 审查不可废（语义层只有它能查），但它的产出必须被当作"线索"而非"判决"——
判决权属于能被 `python -X utf8` 复现的东西。

## 8.5 防审查者假阳性的工程手段：预声明意图

LLM 审查者的另一个系统性风险：把**有意的设计选择**当缺陷报告
（如"幽默维度内容稀少"——但马可·奥勒留本来就不幽默）。后续案例的解法是在
审查 prompt 里**预声明意图清单**（"以下 N 项是有意为之，不构成缺陷：……"），
张居正/马可/汉密尔顿三案均借此实现零假阳性。
这等于给 evaluator 提供了"设计规格"，让它审"偏离规格"而不是审"偏离它自己的品味"。

## 8.6 终检自我修正：被复盘初稿遗漏的一层闸门

本复盘初稿把质量体系总结为三层。成稿后的终检（2026-06-11）在仓库里发现了一个
初稿完全遗漏的子系统：`evaluation/` 自动评测台——上文 8.1 表中的第 3 层，
此处保留发现过程作为勘误记录：

- **冻结标准测试集**（`runtime/test_sets/mind_distill_standard_zh.json`）：12 用例覆盖
  六种输入类型 + 身后/在世边界探针 + **滥用抵抗**（诱导提供职场打压手段，测拒绝与转向）+
  格式遵从 + 多轮口号/序数压力
- **跨模型裁判**（`runtime/judge_rubric.json`）：DeepSeek 按 7 指标×5 分打分，10 种失败旗标
  （third_person_drift / ordinal_formula / repeated_slogan / posthumous_impersonation /
  living_person_judgment / unsafe_manipulation / fabricated_fact 等），P0-P2 严重度政策
- **百分制记分卡**（`reports/{slug}/scorecard.json`）：8 维加权 + gate cap 封顶
- **负面 fixtures**（`fixtures/negative/`）：四个故意做坏的 SKILL（缺语言区块/留占位符/
  无溯源/缺边界规则），验证闸门**能抓住坏样本**——对"闸门本身"的回归测试

毛泽东在评测台上的成绩：**总分 89.0（A-，"strong but not benchmark-ready"），
运行时 21/25（P0=0，P1 旗标 11 次）**——与 8.2 节"静态高分+运行时缺陷"的论断互证，
且给出了量化形态。

两条修正后的结论：

1. **初稿"回归资产缺失"的判断是错的。** 冻结回归集早已存在且五月人物全部过台
   （毛/孙/王/曾/费曼/蒋/鲁迅/塞涅卡/张学良/苏轼）；真正缺的是**制度接线**——
   评测台未写进 distill.md，于是**六月批次七人（俾斯麦→张居正）全部绕过了它**。
   基础设施存在但无强制力，正是"个案实践未升格为管线义务"的活反例。
2. **复盘方法论的教训：叙事会撒谎，目录树不会。** 本复盘的数据收集跟着
   "会话叙事+管线目录"走，没做仓库全目录清点，一个 90+ 文件的子系统被整体漏掉。
   复盘自身也需要"文件完备性前置检查"。

# 第 10 章 新手上手手册

## 10.1 前置条件

- Claude Code 环境 + 本仓库；Python 3.x（PDF 处理需 `pip install pymupdf`）
- 一位你**读得懂**的人物（人文判断力是上限，见 11.2）+ 尽可能多的一手材料
  （PDF/TXT/MD；命名 `{来源简称}_{内容类型}.{ext}`）

## 10.2 从零跑通（十步）

1. 把材料放进 `sources/{slug}/raw/`（slug 小写连字符，如 `wang-yangming`）
2. 运行 `/distill <人物名>`，确认门类推荐（1 主类 + ≤2 副类——它决定框架视角）
3. Stage 1 放行；素材多时编排者会走分片流水线，**等检查点 1 全绿再继续**：
   `python scripts/validate_output.py sources <slug>` 必须 exit 0，
   且 `expression_dna.json` 非空（腔调的命根子）
4. Stage 2 放行；检查点 2 看每条原则是否带具体出处
5. Stage 3 三段式；检查点 3 后**人工读一遍** `frameworks.{zh,en}.json`——
   这是改认知框架最便宜的时刻
6. Stage 4 组装；检查点 4 看合并结构（语言检测头/双区块/无占位符）
7. Stage 5 **必须确认编排者派了隔离子代理**（看到 spawn 才算数，3.6 的教训）
8. PASS 后安装；运行 gallery 校验确认三处（output/gallery/已安装）哈希一致
9. **别急着宣布完成**——先过自动评测台（`evaluation/` 标准 12 题集，通过线 ≥19/25 且
   P0=0），再找非作者的真人聊 ≥8 轮（覆盖六种输入类型），按驯化指南 8 检查点标注
10. 按指南"标准修补方案"查表修补 → 同类问题重测 → 三处同步

## 10.3 常见坑速查表

| # | 症状 | 真实病因 | 处方 |
|---|------|---------|------|
| 1 | Skill 装了不触发 | 文件名不是精确的 `SKILL.md`；或 description 太长太泛 | 改名；description 每语言 1-2 句、精确比全面重要 |

| 4 | 检查点报"素材文件格式错" | 校验器把临时/状态文件当素材 glob 进来了 | 临时物用 `.intermediate` 后缀或移出 processed/ |
| 5 | 并行 worker 连环 ECONNRESET | 并发太高触发限速 | 并发降到 2-3，分批跑 |
| 6 | 长跑中途限额/断线，回来不知从哪续 | 没看状态文件就凭感觉重跑 | `python scripts/task_status.py summary/next <status>`，只重派 pending/failed |
| 7 | 英文决策框架被判"非过滤器" | 校验器对步骤起首词**大小写敏感**（Is/Does/Can/Have） | 英文 gate 步骤以大写疑问词开头 |
| 8 | 发布后 `~/.claude/skills/` 还是旧版 | publish_skill.py 只同步 gallery | 手动 cp 到已安装目录，三处哈希对账 |
| 9 | 产出腔调是"通用分析腔" | expression_dna.json 空/枯瘦，或组装时没消费它 | 检查点 1 死守非空；八维全填；校准示例必须有结构差异 |
| 10 | 测试时人物回答里冒出教学框/系统腔 | 运行时环境输出风格污染 | 测试环境的 output style 也是被测对象，关掉再测 |

## 10.4 三条心法（比步骤更重要）

1. **从最简单的架构开始。** 毛泽东是内联+少量子代理跑通的。分片、状态机、三段合成
   都是被具体故障逼出来的。先跑通，再让故障告诉你哪里需要复杂度。
2. **一切交接走文件，不走对话。** 阶段产物落盘 JSON 是整个体系的承重墙——
   它同时给了你上下文自由（compaction 无伤）、断点续跑（状态机）、跨模型外包（handoff 契约）。
3. **四层闸门一层不能少。** 脚本管格式、隔离 LLM 管语义、评测台管回归、真人对话管行为。
   静态满分不等于运行时合格——4.35 分与八类缺陷可以并存。

# 第 11 章 经验教训总表与未竟之事

## 11.1 十大经验（按可移植性排序）

1. **契约定义在数据上，不在执行者上。** 阶段间以 JSON 文件为契约，执行者可以是子代理、
   编排者本人、甚至另一家模型——管线不变。
2. **静态审查与运行时行为之间永远有沟。** 用真实分布的人类对话测行为，
   用"缺陷根因五分类"修规则——把嘱咐改写成模型无需推理就能执行的动作。
3. **信任排序：脚本断言 > 跨档审查 > 同档审查 > 自我报告。** 确定性校验器是唯一判决者，
   LLM 审查是线索提供者。
4. **审查必须隔离。** 生产者的上下文里装满预期，它读不出自己的错——独立性是信息结构
   问题，不是态度问题。
5. **降级可以，留痕必须。** 质量可降，质量的可见性不可降；无痕降级是延迟爆炸的债务。
6. **越软的产物越要硬的闸门。** 风格、语感这类"说不清"的东西，恰恰需要非空校验、
   维度计数、校准示例这类最机械的保护。
7. **异质评审者并集 > 单一评审者。** ChatGPT/Gemini/Claude/父亲/测试员各自的盲区
   不重合；价值观规则要经受相反方向批评的双向校准。
8. **个案修补晋升工厂标准需要 n≥2。** 模板回流规则防止单案例过拟合，
   也防止普遍缺陷停留在个案层。
9. **恢复逻辑是一等公民。** 长任务必被打断；状态机+阶段锚点+只重派失败单元
   让"继续"两个字成为完整的恢复协议。
10. **沉浸度与护栏厚度成正比。** 第一人称越可信，事实边界越要显式——
    "我不能回答"的拒绝本身可以是人格的一部分（毛泽东边界回答即范本）。

## 11.2 人文壁垒【作者裁决：三者难分伯仲，并列论述】

复盘特设此节回答"文科生做 AI 工程，不可替代的是什么"。作者裁决三者并列：

- **语感辨识力**：表达 DNA 八维、语气词清单、校准示例的 ✅/❌ 之分——这些规则
  能被设计出来，前提是设计者**听得出"这句不像他"**。这只能来自原典阅读量。
  工程师可以照模板填表，但填出来的是"正确的空话"还是"咬合人物本相的细节"，
  差距全在耳朵。
- **价值与边界的伦理判断**：什么该谈、什么慎谈、什么不代言；"建设性"与"粉饰"的分寸；
  "承认结构困难"与"煽动怨恨"的分界——这些护栏的**刻度**没有技术答案。
- **选人选材的史识**：选谁蒸馏、信哪个版本的史料、哪些争议必须进盲区（反右/大跃进/
  文革写进了毛泽东 Skill 的盲区且各配缓解策略）——对人物的判断力决定产品的天花板。

三者的公共底座是同一种能力：**对"人"的精确感知**。管线解决的是把这种感知
无损地编译为机器可执行的规则——工程是放大器，人文是信号源。

# 附录 E 成本定量（token 用量聚合）

**方法**：聚合 44 个会话 JSONL（含 subagent 记录）中每条 assistant 消息的 usage 字段；
"总计"为计费量代理（cache read 按事件重复计数），非去重内容量；不折算货币
（订阅与 API 混合计费，无可靠汇率）。生成脚本 `scripts/_retro_token_usage.py`，
全量明细表 `output/_retro_token_usage.md`。

**全项目**（2026-04-30 至 06-11）：12,853 条助手消息；计费量合计 **17.33 亿 token**
（fresh input 1,531 万 / cache read 15.93 亿 / cache write 1.08 亿 / output 1,683 万）；
**整体缓存命中率 92.8%**。

**头部工作单元**（按总量）：苏轼+内阁规划 2.82 亿 > 稻盛和夫 1.38 亿 > 汉密尔顿 1.20 亿 >
鲁迅 1.19 亿 > 张居正 1.09 亿 > 俾斯麦 1.04 亿 > 达·芬奇 1.02 亿 > ……>
**毛泽东 0.26 亿（22 个工作单元中第 19 位）** > 孙子 0.25 亿 > 曾国藩 0.22 亿。
工厂研发会话（立项/机制升级/复盘）自身消耗 0.88 亿。

**模型输出分布**：opus-4-8 1,107 万 / opus-4-6 354 万 / deepseek-v4-flash 78 万 /
haiku-4.5 71 万 / fable-5 37 万（本复盘）/ sonnet-4-6 26 万 / deepseek-v4-pro 10 万。

三条解读：

1. **最早的完整蒸馏也是最便宜的之一。** 毛泽东总量 2,589 万、输出 30.1 万 token，
   仅为后期人物的 1/4 至 1/11——简单架构（内联+少量子代理）+ 小语料（33 万字）。
   后期成本增长买到的是语料覆盖（24MB 级全集）与审查严格度（4.35→4.9）。
   复杂度的钱花在了哪里，账上看得见——这与 2.1 节"只在需要时增加复杂度"互为印证。
2. **92.8% 缓存命中率验证了"阶段门+长会话"的成本结构。** 阶段间停顿基本不破坏前缀缓存，
   高命中把 17 亿名义计费量的实际成本压到了零头。鲁迅行是反例孤本：fresh input 511 万、
   cache write 为 0——那次蒸馏全程跑在 deepseek-v4-flash 上（无前缀缓存语义），
   fresh input 是同体量人物的 15-25 倍。**跨厂跑管线的真实代价主要是缓存损失**，
   这给 6.2 的成本路由补上了定量注脚。
3. **模型分布与成本路由纪律对账吻合**：opus 系输出占 87%（编排与关键合成），
   haiku + DeepSeek 合计约 9%（worker 脏活、外包提取与评测裁判）。
   "贵模型做判断、便宜模型做批量"不只是写在文档里的原则，也是账面上的事实。
