# Skill Package v6 设计规格：厚核心 + 四附件，中文优先

**日期：** 2026-08-23
**状态：** 待作者审阅
**影响面：** `CLAUDE.md` Rule 4、`config/defaults.json`、`commands/distill.md`、`templates/`、`agents/`、`scripts/validate_output.py`、`scripts/publish_skill.py`、`evaluation/regression-protocol.md`

## 一、问题陈述与实测证据

本设计不基于直觉，基于对 21 个已安装 skill 与 `zhang-juzheng` 全套中间产物的实测。

### 1.1 「单薄」是构成问题，不是体积问题

对 21 个已安装 wisdom skill 逐一切分 `## English` / `## 中文版` 区块，按 CJK≈1.0 tok/char、拉丁≈0.25 tok/char 估算：

| 指标 | 数值 |
|---|---|
| 平均 `SKILL.md` 恒载成本 | **19,682 tok** |
| 其中英文镜像 | **9,269 tok（48%）** |
| 其中中文正文 | 9,913 tok（52%） |
| mao-advisory 一次完整推演的自适应注入 | 12–20K tok（`ADVISORY_PIPELINE_BLUEPRINT.md:126`） |

结论：工厂产出的恒载上下文**已经不小于** mao-advisory 的按需注入总量，但近一半预算是中文用户永远不读的英文镜像，剩下一半又摊得很薄。深度不足源于**预算错配**，不是文件太小。

### 1.2 证据存活率 1.8%

以 `zhang-juzheng` 全链路计量（脚本可复现）：

| 环节 | 数量 |
|---|---|
| `sources/zhang-juzheng/raw/` 原始语料 | 25,072,003 B（13 文件） |
| 分片 | 99 shards / 12 MB |
| 精选提取（4 个 JSON 合计） | **152 条 / 17,029 字** |
| 在最终 `SKILL.md` 中留下逐字痕迹的提取 | **5 条** |
| 最终逐字引文总量（原则原文＋标志性名言） | **307 字 = 精选语料的 1.80%** |
| 提取出的原则 → 出厂 | 15 → zh 7 / en 6 |
| 提取出的名言 → 出厂 | 10 → zh 7 / en 6 |
| 提取出的语感样本 → 出厂 | 26 条 → 6 个 seed |
| **出厂实战案例** | **0（工厂无案例层）** |

### 1.3 溯源链断裂，且现有闸门未拦住

出厂 `SKILL.md` 中原则 1 的引文为：

> 「如此则月有考，岁有稽，名必中实，事可责成。」

该字符串**不存在于** `sources/zhang-juzheng/` 下任何文件——99 个分片全无，`user_sources.json` 全无。`raw/` 中三个独立见证（张居正全集、张居正奏疏集上、朱东润《张居正大传》）一致读作：

> 「如此，月有考，岁有稽，**不惟使**声必中实，事可责成」

即出厂引文是**邻近文本的缝合改写**，非连续逐字引用——归一化后 17 字中只有开头 3 字能在语料中找到。而 Stage 5 隔离评审给出的判定是「7/7 sampled quotes EXACT」。

> 实测补充（2026-08-23，Task 1 完成后用真实实现重跑）：该批 14 条出厂引文中 **4 条**不是逐字引用，非仅此一条。另两类缺陷为字符讹误（「毋得彼此**推护**，徒**记空言**」，语料作「推诿」「托空言」）与静默省略（「须慎之于始；既得其人」吞掉了原文的「务求相应」）。

> 注：`名` vs `声` 可能是 OCR 讹字，出厂文本未必比语料更错。要害在于——**管线中没有任何机制能机器判定这件事**，LLM 评审也没能判定。

### 1.4 mao-advisory 自身的数据反对过度切碎

来自 mao 仓库的消融实验记录：

- **留一消融**：9 个模块中 **7 个未检出独立增量贡献**（M1/M2/M3/M5/M6/M8/M9 均 4/4→4/4，p=1.0，Holm p=1.0）。仅 M4（8/8→4/8）与 M7（8/8→2/8）退化，且二者仍未过家族级 Holm 显著性。
- **路由节点消融**：删除显式分类路由节点后 K0 28/28 vs 28/28，McNemar p=1.0。
- **≤5 模块上限实际挤掉了需要的模块**：`smoke_B_junchi.md:197` 记录「受『≤5 模块』约束…**未单独加载 M7**」——而 M7 恰是仅有的两个消融证明有影响的模块之一。
- 但**未发现**模型读不到 spoke 文件的记录：`gotchas.md` 6 条运行期陷阱**零条**与加载相关。

解读（谨慎，与原文档同调）：这些结果不证明模块冗余。但它们表明，切碎带来的收益是**路由优雅**，不是可测量的能力提升；而按需加载的**选择环节**确实失手过。因此新格式把风险放在「选择」而非「读取」上：核心必须自足，附件的读取触发条件写死在响应策略里，不交给模型临场判断。

### 1.5 复盘未记录过「单薄」

必须诚实标注：`docs/retrospective-mao-distillation.zh.md` 中**没有**任何「Skill 太薄 / 材料被砍」的记录。已记录的运行期缺陷是**通用 AI 分析腔**（RETRO:280、946）与八类套路化缺陷（RETRO:760）。「太单薄」是作者 2026-08-23 从实际使用中提出的**新观察**，本设计据此立项。

同时复盘记录了一条与本设计直接冲突的既有张力（RETRO:775）：

> 「深度匹配复杂度」vs「展现完整框架」——需显式优先级排序

v6 的分层正是这条张力的结构性解法：**核心层承载完整框架，附件层承载深度**，二者不再争夺同一段预算。

## 二、设计目标与非目标

### 目标

1. 中文运行时深度显著提升，且**恒载上下文不高于今日**。
2. 出厂物从「一个配置文件」变成「一套可读、可核、可用的资产包」。
3. 引文溯源变成**确定性可校验**，不再依赖 LLM 评审抽查。
4. 英文版从默认负担降级为**按需产物**。

### 非目标

- **不做调度枢纽**。`SKILL.md` 永远是一份自足的完整框架，不是路由表。只读 `SKILL.md` 的模型，表现必须不低于今日。
- 不回改存量 24 个 skill。
- 不引入运行期联网、不引入模块数量上限式的按需选择机制。

## 三、包结构

```
{slug}-wisdom/
├── SKILL.md              # 恒载 · 纯中文 · 完整框架 · ≤500 行 / ~15K tok
└── references/
    ├── cases.md          # 按需 · 实战案例库 · ~4K tok
    ├── evidence.md       # 按需 · 证据卡（逐字原文） · ~3K tok
    └── voice.md          # 按需 · 语感样本库 · ~2K tok
```

`人物档案.md` **不进 skill 包**——它是给人读的，进 `gallery/{slug}/` 与 `output/{slug}/`，不进 `~/.claude/skills/`。理由：模型每次扫描 skill 目录时不应看到一份它不该读的长文档，且它与 `SKILL.md` 内容高度重叠，误读会造成第三人称叙述漂移（违反第一人称沉浸铁律）。

### 3.1 SKILL.md（恒载层）

保留今日 `## 中文版` 区块的**全部**章节，去掉语言检测头与 `## English` 区块，并做两处加厚 + 一处新增：

**加厚 A：原则数量 7 → 9–11**
`config/defaults.json` 的 `max_principles` 由 8 提到 11，`min_principles` 由 5 提到 8。Stage 3 现有的 9–15 个 principle cluster 足以支撑（`zhang-juzheng` 有 9 个 cluster 却只出厂 7 条原则）。

上限定在 11 而非 12 是算出来的，不是拍的：见下方预算表——12 条 × 900 字会撑到约 535 行，突破 P6 的 500 行硬闸门。

**加厚 B：每条原则从 ~470 字扩到 ~900 字**
现有字段（实测 `zhang-juzheng` 原则 1）：`explanation` 175 + `decision_rule` 94 + `modern_scenario` 61 + `how_it_applies` 72 + `outcome_logic` 70 ≈ 470 字。

新增两个字段，取自 mao 模块解剖（`MODULE_SECTIONS` 六节中的两节）：

| 新字段 | 内容 | 来源依据 |
|---|---|---|
| `failure_boundary`（失效边界） | 这条原则**在什么条件下不适用**，误用会导致什么 | mao 每个模块 frontmatter 强制 `失效条件`；工厂今日只有全局盲区，无**逐原则**失效边界 |
| `prerequisite_intel`（情报前提） | 应用这条原则前**必须先查明什么** | mao 的「情报需求模板」节 |

这两项直接对治复盘记录的运行期缺陷 #5（建议总收束到同一层次）与 #6（边界规则触发失灵）——把边界判断从全局章节下沉到每条原则，模型在选原则时就已带着边界。

**新增 C：案例索引表**
```markdown
## 案例索引

| 案例 | 触发情境 | 对应原则 |
|---|---|---|
| 立考成簿定期限 | 决议已发但无人追责 | 原则 1、3 |
| 夺情之争 | 「我不可替代」成为破例理由 | 原则 3（反例） |
| …… | | |

> 情境与上表某行相符时，读 `references/cases.md` 中对应条目再作答。
```

索引常驻核心（模型永远知道有什么、何时该开），正文在附件（不占恒载）。**这是 v6 与 mao-advisory 的分界线**：mao 把「有什么」也放进了按需层，于是需要一个路由表和一个 ≤5 上限；v6 把「有什么」留在恒载层，附件只装正文。

**新增 D：附件读取触发条件写进响应策略**
在「按输入类型适配」下增加确定性触发行，不用模型自由裁量：

| 输入类型 | 强制动作 |
|---|---|
| 用户问出处 / 质疑真伪 / 「他真说过吗」 | 读 `references/evidence.md`，只引用其中逐字条目 |
| 用户描述具体处境且命中案例索引某行 | 读 `references/cases.md` 对应条目 |
| 同一对话中已连续 2 轮结构趋同 | 读 `references/voice.md` 取样重置语感 |

**预算（实算，非估计）：**

以 `zhang-juzheng` 实测为基：今日 ZH 区块 11,360 字 = 原则层 3,290 字（7×470）+ 其余章节 8,070 字；行密度实测 36.6 字/行。

| 原则数 × 900 字 | 全文字数 | ≈tok（CJK 1.0） | ≈行数 | 占今日恒载(19,682 tok) |
|---|---|---|---|---|
| 9 | 16,870 | 16,870 | 461 | **86%** |
| 10 | 17,770 | 17,770 | 486 | 90% |
| 12 | 19,570 | 19,570 | **535 ✗ 破闸门** | 99% |

取值：**9–11 条，≤500 行，约 17–18K tok**——即恒载较今日**低 10–14%**，而原则层本身从 3,290 字增至 8,100–9,900 字（**2.5–3 倍**）。「深度翻倍」指的是原则层，不是全文；全文因其余章节不变而只小幅下降。

### 3.2 references/cases.md（案例库）

工厂今日**零案例层**，这是与 mao-advisory 差距最大处，也是「单薄」感最直接的解药。

格式，每例：

```markdown
### 案例 N：{标题}（case_id: {slug}-{key}-{year}，{tier}）

**情境：** 当时的客观处境，含约束条件。
**此人如何判断：** 第一人称重述其推理路径，挂到具体原则。
**实际结局：** 发生了什么。
**若换一种做法：** 反事实推演（一句）。
**出处：** 篇目级引用 + confidence。
```

硬闸门（借 mao A4 gate）：
- 每个 principle cluster **≥2 例**
- 全库**至少 1 个反例**（此人判断失误或原则误用的案例）——防止案例库退化成颂扬集
- 每例必须有 `case_id` 与 confidence 分级
- 每例出处须篇目级，且必须过 §五 的逐字校验

`tier` 取值沿用工厂既有 confidence 语义：`high`（用户一手材料）/ `medium`（网络或转述）。

### 3.3 references/evidence.md（证据卡）

每条原则一张卡，承载**逐字**原文：

```markdown
### 原则 N：{名称}

> {逐字原文，不改一字}

- 出处：{书名}·{篇目}（{年份}）
- 语料位置：`sources/{slug}/raw/{文件名}` 或 `processed/{文件}` 第 N 条
- confidence：high / medium
- 现代转译：{SKILL.md 中那句「决策规则」如何从这段原文推出}
```

这一层同时是 §五 provenance 校验器的输入端。目标把逐字证据存活率从 **1.8% 提到 ≥15%**，并让每一条都可机器回溯。

**存活率定义（避免歧义）：** 分子 = `SKILL.md` 与 `references/evidence.md` 中逐字引文的去重字数；分母 = `sources/{slug}/processed/` 四个提取文件的 `extracts[].text` 总字数（`zhang-juzheng` = 17,029 字）。15% ≈ 2,554 字。分子去重是必要的——同一段原文同时出现在核心与证据卡不重复计数。

### 3.4 references/voice.md（语感样本库）

现状：26 条 `expression_dna` 提取 → 压成 6 个 `sample_seeds` → `SKILL.md` 里一张 8 维表。样本库把 20+ 条原始语料带标注全部保留：

```markdown
### 样本 N（维度：{句式/修辞/语气/…}）

> {原文片段}

**为什么像他：** {一句标注}
**误写成通用分析腔会变成：** {反例改写}
```

「误写成通用分析腔会变成」这一行是新的——复盘把「通用 AI 分析腔」列为头号运行期缺陷（RETRO:280、946），正例＋反例对照比单列正例有效。

### 3.5 人物档案.md（人读，不进 skill 包）

一份可读的蒸馏成果报告，落 `output/{slug}/人物档案.md` 与 `gallery/{slug}/人物档案.md`：

1. 语料规模与来源清单（含 OCR 质量、已知讹字）
2. 原则推导链：cluster → 候选原则 → 出厂原则，**含被舍弃的候选及舍弃理由**
3. 盲区与缓解
4. 质量审查结论与 distill_confidence
5. 已知风险（误归属陷阱、OCR 讹字、后世注评混入等）

这是把管线内部的判断过程变成交付物——今日这些信息散在 `framework_core.json`、`review.md`、`framework_alignment_review.md` 里，无人可读。

## 四、语言策略（Rule 4 重写）

### 4.1 默认单语

默认只产出中文。`config/defaults.json` → `"languages": ["zh"]`。

Stage 3B 只跑中文合成器，Stage 3C 对齐审查降级为**中文自检**（框架步骤是否全为过滤器型、盲区是否带缓解）。Stage 4 不再合并，不再有语言检测头。

### 4.2 英文版为独立 skill，按需生成

作者裁决：英文版落 `{slug}-wisdom-en/`，**独立 skill 目录**。

触发点：Stage 6 安装完成后，编排者询问「是否生成英文版？」。选是则跑 EN 分支——复用语言中立的 `framework_core.json`，只需 3B-en + 4-en + 5-en，Rule 4 的「独立重构而非互译」在 EN 分支内完整保留。

**路由收益（非预期但真实）：** 今日 24 个 skill 的 description 全是中英混排，等于 24 条 description 同时匹配中英文查询。拆开后 ZH 包 description 纯中文、EN 包纯英文，路由分离度**提高**。这部分缓解复盘记录的 P1 欠账「24 个 skill 同装，description 路由层误触发率从未测过」（RETRO:1020）。

**已识别风险：** gallery 条目数翻倍；`index.json` 与 `publish_skill.py` 需支持 `lang` 字段与 `-en` 后缀。EN 包沿用同一套 v6 结构（英文附件同步产出）。

### 4.3 被放弃的既有资产

Rule 4 原表述「翻译传递的是语言，独立重构传递的是认知框架」（RETRO:99）是一条**有效且有理由**的设计原则，本次不是否定它，而是把它从「每次必付」改为「按需支付」。支持这一改动的既有事实：英文侧本就未纳入回归——冻结的 12 题标准集是纯中文（`mind_distill_standard_zh.json`），复盘 P1 明列欠账「补英文标准测试集」（RETRO:1008）。即默认关闭 EN 分支，实际上是把一个**从未被测过**的分支从默认路径移出。

## 五、新增确定性闸门

新增 `scripts/verify_provenance.py`，作为 `validate_output.py package {slug}` 的一部分。全部规则式，不依赖 LLM 打分（借 mao「前三重全部规则式，防闭环自评」原则）。

| 检查 | 规则 | 拦截的真实缺陷 |
|---|---|---|
| **P1 引文闭环** | `SKILL.md` 中每条 `> 引文` 与「原文出处」必须**逐字**出现在 `references/evidence.md` | 出厂引文与证据卡不一致 |
| **P2 语料闭环** | `evidence.md` 中每条逐字原文必须**逐字**出现在 `sources/{slug}/raw/` 或 `processed/` 某文件中（标点与空白归一化后比对） | **§1.3 的「月有考」缺陷** |
| **P3 路径可解** | `SKILL.md` 中每个反引号路径必须能解析到实际文件 | mao 因「空指的工作坊路由」加过同款检查（`CLAUDE.md:54`） |
| **P4 案例覆盖** | 每个 principle cluster ≥2 例；全库 ≥1 反例 | 案例层退化为颂扬集 |
| **P5 索引一致** | `SKILL.md` 案例索引表每行必须对应 `cases.md` 中一个 `case_id`，反之亦然 | 索引与正文漂移 |
| **P6 核心自足** | `SKILL.md` ≤500 行；且在**忽略 `references/` 是否存在**的前提下，仍含今日校验器要求的全部 8 个必需章节（身份卡/响应策略/核心原则/决策框架/已知盲区/表达风格 DNA/价值取向与反模式/溯源），每章非空 | 核心退化成调度表 |

P3 与 P6 分工：P3 在附件齐备时检查指针不悬空；P6 只检查**章节存在性与非空**，不检查指针——因此二者不冲突。新增的「案例索引」章不计入 P6 的 8 章必需集（它本就是指向附件的），但计入 P5。

P2 允许一条**显式豁免通道**：若逐字比对失败但作者判定出厂文本正确（如 OCR 讹字），须在 `evidence.md` 该条目写 `textual_note:` 说明分歧，校验器接受带 `textual_note` 的条目但在报告中列出。分歧记录在案，而不是静默放过。

P6 的「删去 references 后仍完整」是**防调度化的结构保险**——只要这条在，包就不可能滑向 mao-advisory 的形态。

## 七、风险与缓解

| 风险 | 缓解 |
|---|---|
| **模型不读附件，附件层沦为死重** | 触发条件写死在响应策略（非模型裁量）＋ 索引常驻核心 ＋ 回归协议实测读取行为。这是本设计最大的未验证假设，必须在样板人物上先测。 |
| 核心加厚后仍超 500 行 | P6 硬闸门拦截；超限则减原则数而非砍每条深度（深度是本次目标） |
| 案例库编造 | case-builder 沿用 mao 的 proof-line 纪律；每例过 P2 逐字校验；≥1 反例要求 |
| EN 包使 gallery 条目翻倍、路由变复杂 | description 语言纯化实际改善路由；`index.json` 加 `lang` 字段便于筛选 |
| 存量 24 个 skill 与新格式并存 | `index.json` 加 `format_version` 字段；两种格式长期共存是可接受代价（作者裁决） |
| 附件读取消耗额外轮次/延迟 | 只有三类明确输入会触发；多数对话仍是纯恒载路径 |

## 八、验收标准

新格式在**一个样板人物**上跑通并满足：

1. `python scripts/validate_output.py package {slug}` 退出码 0
2. `SKILL.md` ≤500 行、纯中文、无语言检测头
3. 逐字证据存活率 ≥15%（今日 1.8%）
4. 每 principle cluster ≥2 案例，全库 ≥1 反例
5. P2 逐字语料闭环全过（或分歧均有 `textual_note`）
6. ≥8 轮压测中，附件至少被正确触发读取 **2 次**，且核心层在未读附件的轮次里表现不低于旧格式
7. `人物档案.md` 可读、含被舍弃候选原则及理由

第 6 条是真正的成败判据——其余都是形式合规。

## 九、已定默认（作者可推翻）

以下两项按「选一个并写明」处理，不作为开放问题挂起：

- **样板人物 = `zhang-juzheng`。** 理由：语料 25MB、9 个 cluster 足够撑 9–11 条原则、全套中间产物齐备，且 §1.3 的溯源缺陷正出在它身上——P2 闸门若有效，第一次跑就该把它抓出来。这是自带阳性对照的样本。
- **P2 逐字比对归一化 = 标点/空白/繁简三者均归一后比对。** 理由：`张居正奏疏集` 为繁体、`全集` 为简体，同一段话在语料中本就有两个字形，不做繁简归一会产生大量假阳性。字形来源写入该条目的 `textual_note`。

若作者不同意任一项，改动仅影响实施顺序，不影响本设计的结构。
